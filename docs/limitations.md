# Limitations

- This checkout starts on an Apple Silicon Mac. Real NVIDIA/vLLM experiments, kernel compatibility, GPU memory fit, GPU telemetry, and empirical optimization findings require verification on an NVIDIA host.
- The benchmark uses the completions endpoint with synthetic token IDs. It measures serving systems rather than chat-template overhead, semantic realism or answer quality. Structured output/quality regression evaluation is a separate optional study; raw outputs are preserved for it.
- Client TTFT is first visible content delivery; TPOT is an estimate from chunk boundaries and final server usage. Exact generation timing needs token-aware server instrumentation.
- The whole workload is retained in memory and raw artifacts. Worker/task and backlog counts are bounded; arbitrarily huge request counts or context sizes can still exceed client RAM/disk. Use modest sweeps first.
- The server API does not attest model revision, runtime flags, container digest, GPU identity or all runtime library versions. Manifests distinguish declared and observed information. Collect container inspection evidence when publishing.
- GPU monitoring through NVML is local and may be unavailable in a container without GPU utility access. Prometheus scraping and NVML sampling are best effort unless `require_gpu` is set; missing fields and errors are explicit. Short runs may have very few samples.
- vLLM counters do not expose all client HTTP failures. The optional benchmark exporter provides failures, drops and cancellations for Grafana; it must be enabled and reachable from Prometheus. Very short runs can fall between scrapes, so raw artifacts remain the exact reliability record. The separate mock-failure panel is fixture-only.
- Cancellation and timeout finalize observations and reports. SIGKILL, disk exhaustion and machine power loss cannot guarantee final Parquet files; the flushed JSONL journal and running manifest provide partial evidence, not a transparent resume mechanism.
- Experiment matrices run in deterministic order. Ambient thermal, clocks, shared-host activity, caching, and repeated workload order can affect results. No exact GPU timing reproducibility is claimed.
- Plot labels and comparability checks cannot establish causality. Single-run comparisons and three-repetition descriptive ranges are not statistical significance tests. A model revision or client-source change is intentionally inconclusive under strict regression checks.
- Docker tags and client constraints are pinned examples; immutable image digests and target-specific tokenizer/GPU dependency locks should be recorded for a published study. GPU optional extras and deployment images are validated separately from the CPU test environment.
- The platform does not provision paid infrastructure or publish artifacts automatically. The original proposal's real-GPU case study and publication criteria remain outstanding until measured and explicitly published.
